# Native pond motor PPO, exercise v2

No training runs when building or opening Godot. This is a separately gated
candidate motor study, not the next navigation chooser and not a restoration of
the retired historical driver. The original saved amplitude package stays intact.
Root owns the finite protocol, prerequisite qualification, execution and results.

The candidate actor is41→32→32→4; the auxiliary critic is41→32→32→1. The initial
actor copies all2532 saved weights. Holding amplitude remains the original
0.26211655139923096. Fixed latent Gaussian sigma is0.10. Physical commands are
`tanh(gain*z)` for Hold and `tanh(z)` for moving tasks; stored PPO likelihoods
score the original unscaled Gaussian z. No chooser, route or bank-steering rule
is added here. Exercise v2 uses observation schema5/task2: Straight keeps all
original lane/depth feedback; Turn alone removes horizontal world lane error.
Earlier turn31 files remain separate and stopped.

The sampled training mix is25%Hold,25%Straight and50%requested turns, with signed
5/15/30/60/90° requests latched after40 controls of a fresh episode. Turn
observations remove horizontal world-space lane error before body rotation;
Straight and holding keep their original full observations. Joint/filter/body state
persists across64-control collection boundaries. Accepted depth>5mm or tilt>30°
is a genuine task failure with reward−1 and no bootstrap. A clean1200-control
episode boundary is an explicitly recorded truncation with the pre-reset final
critic value. Neither kind of training reset is a deployed recovery.

Physical/certificate/numerical failures reject the entire batch before GAE or
Adam. Every batch stores initial world/task state, original collection actor/
critic weights, observations, original latent actions/logp, reward/value/terminal
masks and attempted controls/substeps. Whole-body first-PRE/candidate states are
retained in the failed raw-state dump. Every valid batch also rechecks all stored
latent likelihoods under unchanged collection weights before GAE/Adam.

The full training allocation is32updates×512worlds×64controls=1,048,576 physical
controls and at most10,485,7605ms substeps. Four epochs of eight4096-row
minibatches give32 actor+32 critic Adam calls/update, at most2048 combined.
Adam LR1e−5, default betas/epsilon, global gradient clipping1; PPO clip0.1,
gamma0.995, lambda0.95, fixed sigma0.10. Approximate KL above0.05 stops the study;
a full-rollout audit also checks the final actor after the last Adam call. A
partial optimizer update never becomes a completed candidate. A raw failed state
is separate from the last whole candidate checkpoint. If collection readback
fails, evidence marks accounting unknown and records conservative scheduled-work
upper bounds; it does not report zero physical work.

One process runs exactly the next eight updates, then stops for external
retention. Candidate checkpoints carry Adam state, all512 worlds/tasks, sampler
serial and aggregate resource counters, so resume does not reset physical state
or expand the allocation. The aggregate native training wall cap is1200seconds
and evidence cap4GiB across all four chunks. Each chunk conservatively charges
an8KiB text-output reserve; checkpoint wall counters conservatively reserve five
seconds for final writes. Work stops with ten seconds reserved for finalization.

Per-transition diagnostics include actual COM X/Z/velocity, depth/tilt,
minimum control gap, episode/kind/control, raw16×16 world-grid occupancy and
occupied count, bank-near/contact time and post-warmup low-speed time. These
reset only for a new training episode; they are never stitched into one claimed
continuous exploration run. Grid counts are not reachable-area coverage and do
not change this turning motor's reward.

## Preparation commands

Configure/build in an isolated folder:

```powershell
cmake -S tools/pond-ppo -B build/pt32/native
cmake --build build/pt32/native --config Release --target pond_ppo pond_ppo_pure --parallel 2
```

`pond_ppo_pure` is a CPU-only checkpoint/GAE/likelihood test. `pond_ppo --describe`
prints source/layout identity without creating a CUDA context. `--preflight
--policy <original-package> --out <new-folder>` checks SHA256, original provenance,
the32 initial task observations and zero-integration geometry preparation. These
commands do not launch physics or optimizer work. A source/compiler/flags
manifest is generated by CMake; changed inputs change the trainer identity.
The physical CUDA translation unit uses normal Release optimization and
`--fmad=false`; the native NN/PPO library keeps its normal optimized profile.
The temporary `--Ofast-compile=max` preparation artifact is not a run target.
Host receipt parsing and source identity live in `admission.cpp`; future host
binding fixes do not require recompiling the physical CUDA kernel. The pure
utility also supports `--describe-host`, `--check-gates CPU GPU PARENT_FNV` and
`--check-protocol PROTOCOL CPU GPU EVAL_FNV PARENT_FNV`. These validate files and
bindings without constructing a GPU context or advancing physical time.

## Root-owned run admission

Only `--run` can collect physics or update weights. Both `--initialize-only` and
`--run` require completed, source-bound physics prerequisites:

- `--policy <immutable-original-package>`
- `--out <new-unique-output-folder>`
- `--protocol <sealed-machine-JSON>`
- `--cpu-gate <passed-v4-result-JSON>` and `--cuda-gate <passed-v4-parity-result-JSON>`
- `--evaluator-source <exact-native-retention-evaluator-identity>`
- `--to-update 8` for initialization/first chunk, then16/24/32 in later chunks.

Machine JSON bindings are root-level scalar keys: protocol_id
`pond-motor-ppo-v2-2026-11-23`, source_identity_fnv1a64 (decimal string from
`--describe`), qualified_physics_source_sha256 (from the same descriptor),
retention_evaluator_source_fnv1a64 (decimal string), ledger_path_absolute,
max_updates32,
worlds512, rollout_controls64, max_wall_seconds1200, max_evidence_bytes4294967296,
cpu_gate_sha256 and cuda_gate_sha256. The driver rejects a static preflight as a
physics receipt. It checks the completed36-case CPU qualification, saved motor,
runtime4/query arithmetic2, CPU protocol `shoreline-product-v4-2026-11-23`, fresh
GPU protocol `shoreline-product-v4-cuda-2026-11-23`, CPU-compatible CUDA arithmetic profile
and matched eight-case128-control CPU/CUDA accounting. The stopped unoptimized
v3 diagnostics cannot admit training. Root independently checks both gate manifests against the
compiled physical-source aggregate before sealing these hashes.

`--initialize-only` copies the original actor, initializes the auxiliary critic,
zero-step Adam state and512 prepared worlds, then saves candidate0 without a
physical step or Adam call. Evaluate candidate0 before the first optimizer call.
The first `--run` requires `--resume <candidate-0>` and its baseline-only native
assessment receipt. Schema3 requires that receipt to bind the exact candidate,
parent, protocol and evaluator and PASS all20 retention cases with the full
30,400controls/304,000substeps and no physical faults. The bound evaluator checks
all28 required long-swim windows, all14 rests and4 short swims. A failed baseline
cannot release any optimizer call. Turning is measured without becoming an entry
requirement for learning the missing skill.

Later continuation requires `--resume <candidate-8/16/24>` and
`--retention-receipt <native-receipt>` binding those same identities and reporting
all20 retention cases/30,400controls/304,000substeps passed. Turning qualification
is reported separately; a retention receipt does not establish navigation or
exploration. The protocol-bound ledger accepts only the last waiting checkpoint,
prevents reinitialization/replay and stops continuation after a failed chunk.

Root must finish physics agreement, preparation/data-path review and the finite
protocol before any run. This README grants no new execution budget and contains
no claim that the unexecuted candidate learns successfully.
